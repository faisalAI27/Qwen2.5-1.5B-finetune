# RunPod inference handoff

This reuses the existing `artifacts/colab/nlp-colab-assets.zip` (917,976,814 bytes), the exact trained adapter and the original quantized base. No training or adapter conversion is needed. The Mac run continues independently. No Pod has been rented or account credit spent by this handoff.

## Choose and launch

1. Sign in at the [RunPod console](https://console.runpod.io/), then choose **Pods → Deploy**, one **RTX 4090 (24 GB)** and **On-Demand**. This is a first benchmark candidate; speed has not been measured on it. The [pricing page](https://www.runpod.io/pricing), checked November 17, 2026, lists $0.89/hour; the actual deployment quote and storage are authoritative. Two hours at that GPU rate would cost $1.78 plus storage. Do not infer the full project's cost until development timings are available.
2. Select an official **RunPod PyTorch** template with **Python 3.11 or newer**, Linux and JupyterLab enabled. The project itself still uses isolated MLX CUDA, not the template's PyTorch. Configure roughly **25 GB container disk** and **30 GB persistent volume at `/workspace`**. Larger storage is optional; the existing 918 MB ZIP is sufficient for model transfer.
3. After deployment, use **Connect → Jupyter Lab** (usually port 8888). Official PyTorch templates include JupyterLab. See [connection documentation](https://docs.runpod.io/pods/connect-to-a-pod).
4. In JupyterLab, open `/workspace`, and upload the existing `nlp-colab-assets.zip` and the new `notebooks/runpod_inference.ipynb`. The notebook expects `/workspace/nlp-colab-assets.zip`. Use [SCP or runpodctl](https://docs.runpod.io/pods/storage/transfer-files) if browser upload of the ZIP is slow. Keep one exact ZIP; no public Drive link is needed.
5. Open `runpod_inference.ipynb` in RunPod JupyterLab and execute its cells in order. Setup clones the exact source commit recorded in the ZIP, verifies its archive/file hashes, creates `/workspace/nlp-runpod-env`, installs matching CUDA 12 headers, and checks a small GPU operation. It embeds the separate RunPod launcher without modifying any source files covered by the original bundle hashes.
6. Run smoke, then all **45 development outputs**. Inspect their timings and the printed GPU activity before running the benchmark cell. Do not assume a particular speedup over the M1 or T4. The final freeze prints the matched Mac mean and RunPod mean, plus token parity; output-length differences must be considered when interpreting time differences.
7. Run the freeze cell, then test generation, grading and analysis. The benchmark run is **`math500-runpod-cuda-v1`** and the development run is **`runpod-cuda-dev-v1`**. They are independent of both Mac and Colab runs. Existing predictions from other hardware are not resumed or merged. Preserve all partial runs as such.
8. Save/download the latest state snapshot, results, manifests and GPU log before stopping or deleting resources. **Stopping** ends GPU compute billing but persistent storage is still billed. A Pod volume is retained on stop but lost on Pod deletion; a network volume persists independently. See [storage](https://docs.runpod.io/pods/storage/types) and [Pod management](https://docs.runpod.io/pods/manage-pods). An external backup is needed before deleting a Pod that uses only a Pod volume.

## Persistence and validation

All project files, the environment, CUDA cache and Hugging Face cache live under `/workspace`; this must be a persistent volume. State snapshots go to `/workspace/nlp-runpod-state` every five minutes and after each stage, retaining the last two snapshots. A snapshot on the same Pod volume protects against process interruption, not deletion or loss of that volume. Download snapshots or back them up externally. Reuse the exact environment and GPU/driver/runtime for resume; the existing freeze rejects a different runtime.

The helper prints only newly appended log lines, reports GPU activity every 30 seconds and logs it to `results/runpod-gpu.csv`. Those activity samples indicate whether kernels are busy, not complete hardware efficiency. Exact prediction slots remain the authoritative progress record. CUDA JIT/model initialization can take time on the first run.

The RunPod launcher adds its provider name and own SHA-256 to the runtime identity. Original source/model/adapter file checks still run. The notebook refuses to overwrite an existing different launcher in a saved workspace. The RunPod smoke must verify adapter identity and unchanged weights before development or benchmark generation is permitted. Local CPU tests and notebook parsing do not constitute a successful RunPod GPU test.

The legacy CUDA script and package retain `colab` in some source names, but RunPod output IDs and runtime identities are distinct. No GPU-specific paper writer is invoked automatically: the research report must later distinguish M1 training, M1 inference, T4 inference and RunPod inference, with actual hardware metadata and honest coverage.
